# Hindsight measured ingestion: first rollout

This GitOps change keeps Hindsight 0.9.2 at one API with its internal worker, retain concurrency 1, global LLM concurrency 2, both separate banks, pinned image digests, routes, auth PVC and storage. It enables native metrics and a new safe operational log collection lane. Before that logging change is promoted, the existing broad collector still forwards API source logs; current INFO/JSON logging is already active and may contain free text. A metrics-only packet does not sanitize that existing stream. A retain concurrency 2 trial is a separate reviewed change after the baseline is healthy.

## Signals and limits

`ai/hindsight-api` is scraped at `/metrics` every 30 seconds through an additional Prometheus service-account GET `/metrics` Cilium lane. The three previously approved API clients retain direct TCP 8888 access, including direct `/metrics`; gateway routing alone does not make metrics exclusive. A separate listener or endpoint authorization needs its own reviewed design. The dashboard discovers `bank_id` values dynamically. `hindsight_async_operations` counts status rows. Pending includes future retry-deferred children; failed includes historical failures. Neither is runnable queue depth, oldest age nor a new-failure counter. `batch_retain` parents are shown separately and excluded from the retain-child warning. `hindsight_operation_operations_total{source="worker"}` measures completions, and includes executor-handled failures; its `success` label is not a final-failure verdict. Repeated handled failures can suppress the progress warning. Terminal success/failure instrumentation is needed before any success SLO or exact new-failure claim. `hindsight_llm_calls_total` and duration buckets provide outcomes and latency; inbound HTTP 429 is not a Codex provider 429. Native metrics do not report provider permit wait or per-bank fairness.

The warning requires pending retain children now and 10 minutes earlier, no worker completion in the last 10 minutes, and then a 10-minute rule hold. For a continuously present new bank this first fires near 20 minutes, subject to scrape and evaluation timing. It is a **status-only, deferred-inclusive progress heuristic**, never measured job age. A new bank with no completion counter cannot fire at first sight. Deferred-only work can eventually alert; check `next_retry_at` using an approved read-only operator query before intervening. The 10-minute window is provisional: before Obsidian work, 1,376 `devb0x` completions had p99 end-to-end 283.955 seconds, so twice that rounded up is 10 minutes. That historical cohort is a reference, not proof of current healthy service. Use this historical reference for the initial warning; compare passively with later ordinary activity. The earlier Obsidian timing sample was congested and is not a healthy reference. Expected audience is the cluster operator with existing Prometheus/Grafana access. Root measured **1,168** current unlabelled `hindsight_*` series across 26 metric names, with bank/backlog opt-ins still disabled. The provisional complete-family instantaneous threshold **4,000** and 30-minute distinct-series threshold **6,000** allow estimated two-bank multiplicity and headroom; neither is a measured bank-enabled healthy baseline. Both must be reviewed against an ordinary labelled scrape after rollout. Histogram buckets, sums, counts and short-lived bank IDs are included. Dynamic bank labels require a pre-promotion review of identifier disclosure and unexpected series growth, not a static allowlist. Prometheus and Grafana show warnings; Alertmanager still routes to `null`, so paging is not configured.

`HindsightMetricsAbsent` checks missing/down targets; `HindsightNativeGaugeAbsent` checks the pinned always registered DB pool waiting gauge when `up=1`. The callback can omit the gauge on an internal exception, so this warns about native exposition rather than proving a particular root cause. Quiet operation/backlog families can legitimately be absent. For those families, compare prior presence and independently verified activity before calling a gap abnormal; a quiet bank with no samples remains **unknown**. Native metrics cannot detect every missing family or prove that a zero status gauge represents completed source coverage.

## Read-only timing baseline

Run `python3 scripts/hindsight-timing-baseline.py --start-utc 2026-10-03T09:00:00Z --end-utc 2026-10-03T09:30:00Z` using your chosen explicit UTC `[start,end)` bounds and a read-only PostgreSQL account supplied through standard `PG*` environment variables in the protected operator environment. The query uses a 15-second statement timeout, a 25-second total subprocess deadline including stdout drain and process reaping, a read-only transaction, and at most 5,000 most recently completed eligible rows per bank and operation type in a 30-to-1,440-minute window; the helper reports each group's eligible count, coverage and truncation flag. It emits aggregate per-bank/type quantiles, sample counts, sampled completion time range and cohort metadata. No operation IDs, payloads, error text, raw rows or credentials are emitted. Any invalid row or query/input failure reports only a fixed error category. `--input` is for synthetic JSONL tests only.

The cohort is rows **completed within the requested UTC bounds**, with zero *recorded* retries, non-parent type and valid timestamps. `created_at` may predate that window; deferrals do not increment `retry_count`. Queue seconds therefore includes old congestion and is not eligible wait. Claimed-wall seconds includes permit waits, task-internal retries and folding. The 1,376 completed devb0x retain jobs before Obsidian work are the initial historical reference. A quiet bank is reported as missing, never fabricated healthy. A truncated group quantile covers only its sampled recent rows. Later comparisons use passive ordinary traffic, not artificial memories or paid canaries.

## Logging boundary

The chart's default broad Promtail job is preserved except for API exclusions. Its verified predicate uses the pinned Deployment's ReplicaSet controller, pod prefix and three chart labels; the safe job uses the same predicate plus the `api` container. A second broad exclusion quarantines every `ai/hindsight-api-*` pod if owner or labels drift, so uncertain API logs cannot fall into the raw lane. A different workload with that prefix and different metadata is also quarantined, not silently classified as Hindsight. The `ai` namespace is trusted for pod creation; Kubernetes metadata does not authenticate an actor who can create or alter pods there. Review namespace pod-create authority before promotion. The safe job accepts only exact logger `hindsight_api.worker.poller` with the pinned 0.9.2 worker message shapes `scheduled for retry at`, `deferred until`, `timed out:` and `failed:`, and emits fixed JSON with category and UUID in the body. UUID is not a Loki label. All free-form suffixes, arbitrary exception fields, malformed lines and raw source entries over 4,096 bytes are discarded before Docker/CRI unwrapping. Inspect Promtail drop counters `hindsight_unrecognized` and `hindsight_oversized`: expect nonzero unknown counts from ordinary API INFO lines, so compare each 30-minute window with its own baseline; compare accepted categories with matching protected source events in the same UTC window. Zero accepted lines is expected when there are no matching exceptional source events. Investigate a source/accepted mismatch or a drop-rate change relative to API log volume. Keep transformed output below 1,024 bytes. The safe job carries a bounded `pod_uid` label for exact per-instance comparisons during a rolling update; one active API plus brief overlap is expected. Running, Failed and Succeeded targets remain eligible while the pod and final node file exist; target eligibility alone does not prove final delivery. Pod deletion, node loss, rotation and unavailable retention still make source coverage unknown. Review Loki series growth and access before promotion. New message shapes remain absent until reviewed.

Loki retains existing data for 14 days; this change does not purge past entries. Node source pod/container logs remain unsanitized and cluster-admin accessible. Never export or paste raw source lines. Promtail is end of life; a collector migration is separate work.

## Promotion, later trial and rollback

Root runs the protected live checks after reviewed Flux promotion. Verify target `up=1`, transformed Loki lines when matching source events exist, Promtail drop counters, API readiness and both-bank recall. Observe ordinary retain activity passively; mark a quiet bank unknown. This first rollout stays at retain 1. Take two adjacent equal **30-minute** UTC windows from passive ordinary activity; extend both equally when coverage is sparse. No fresh two-bank cohort is a prerequisite to this first rollout. Before a later trial, missing source coverage blocks a comparison. Record only counts and p95s: per-bank pending and completions, provider 429, auth refresh errors, task timeouts and failures, recall/reflect p95, LLM p95, DB pool waiting minutes and readiness failures. Obtain provider 429/auth/timeout counts from protected source evidence, never from inbound HTTP 429 or raw exports. If one window is unhealthy, truncated or missing a bank, do not trial retain 2. A quiet bank is unknown; it is never treated as a zero rate eligible for comparison.

Before a later, reviewed retain-2 PR, freeze two healthy windows as reference and predeclare a contiguous, equal-duration 30-minute trial with a first 10-minute check. Abort and revert to retain 1 through reviewed GitOps if **any** provider 429, auth refresh error, worker timeout or readiness failure appears when its two-window baseline count was zero; if a nonzero baseline count doubles in an equal window; if recall or reflect p95 or LLM p95 rises above 1.5 times the worse baseline window; if either bank's completion rate falls below half the lower baseline rate while its pending endpoint exceeds the immediately preceding reference endpoint; or if DB pool waiting persists five minutes. Treat a stalled-retain warning as a prompt to check deferred rows and worker state, not an automatic retry. Preserve global cap 2 and verify both-bank reads and one healthy worker after Flux reconciles. No live patch, restart, bulk retry or direct cluster apply is part of this runbook.

Exact runnable depth/age or new failed-child rates require an approved read-only exporter, a queue-age SLO, pinned claim SQL, restored-DB `EXPLAIN` and a SELECT-only role. A separate worker or autoscaling additionally needs Codex-refresh RWO ownership, drain/replay proof, aggregate provider and database budgets, and per-bank fairness. Security review, public scanner disposition, Josh's protected-workflow merge and root-run live verification remain publication gates.

## Equal-window evidence procedure for a later trial

Choose UTC half-open operator windows `[A,B)` and `[B,C)` of equal duration, normally 30 minutes, and record the three boundaries. Prometheus range selectors evaluated at B include samples in **(A,B]**, so they do not prove exact `[A,B)` event membership. Use the same endpoint convention for every reference/trial window and treat borderline ratios as unknown; obtain validated raw counter deltas if exact membership is required. At each endpoint, evaluate the following **instant** expressions with the query API's `time` set to that endpoint. Retain only numeric aggregate results and the bounds. A missing series is **unknown**, not zero. Each 30-minute window at 30-second scrape interval needs 60 expected samples per stable target; inspect `count_over_time(up{namespace="ai",service="hindsight-api"}[30m])`, target identity, pod UID/container lifecycle and missing/stale series. `min_over_time` alone ignores absent samples. Any scrape or lifecycle gap makes the window unknown. Apply the same coverage test to each five-minute DB-wait slice (10 expected samples). The `bank_id` labels are dynamic; include every bank seen in either window and explicitly mark a quiet bank absent. Match the query endpoint to the window endpoint, rather than taking values from two different dashboard refreshes.

| Evidence | PromQL at window end | Interpretation |
|---|---|---|
| Retain completions | `sum by (bank_id) (increase(hindsight_operation_operations_total{namespace="ai",operation="retain",source="worker"}[30m]))` | Finite nonnegative Prometheus estimate per bank, including handled failures. `increase` extrapolates and can be fractional (an observed one increment yielded 1.0344827586206897); never round to an exact event count. Require covered samples and stable target identity. |
| Pending retain children | `sum by (bank_id) (hindsight_async_operations{namespace="ai",operation_type="retain",status="pending"})` | End-of-window status; includes deferred rows, excludes batch parents. |
| LLM p95 | `histogram_quantile(0.95, sum by (le,scope) (increase(hindsight_llm_duration_seconds_bucket{namespace="ai"}[30m])))` | Compare exact matching scope keys across all three windows; a zero bucket denominator is unknown. |
| Recall/reflect p95 | `histogram_quantile(0.95, sum by (le,operation,bank_id) (increase(hindsight_operation_duration_seconds_bucket{namespace="ai",operation=~"recall\|reflect"}[30m])))` | Compare exact matching bank/operation keys across all three windows; no observations means unknown. |
| DB waiting | At every 30-second evaluation step from A+5m through B, evaluate `min_over_time(hindsight_db_pool_waiting{namespace="ai"}[5m]) > 0`. | OR the covered per-step booleans into one `db_wait_five_minutes` flag. A wait at A+10 through A+15 must count even if clear by B. Require 10 samples and the same target identity in **every** five-minute slice; a missing slice is unknown. |
| Scrape and readiness | `min_over_time(up{namespace="ai",service="hindsight-api"}[30m])` and `min_over_time(kube_pod_container_status_ready{namespace="ai",pod=~"hindsight-api-.*",container="api"}[30m])` | Both must be 1 and have all expected samples for the full window; missing/stale series or an unaccounted pod replacement means incomplete coverage. Readiness is not inferred from HTTP 429. |

For each later comparison window, independently inventory **every** API pod/container instance intersecting `[start,end)`: record only pod UID, container ID, log source (`current` or `previous`), lifecycle and covered UTC intervals, first/last source timestamp and source line count. A physical `(pod_uid,container_id)` appears once; a restart has a different container ID even if its pod UID is unchanged. Each instance's declared source interval must cover its **own** lifecycle intersection with the window, before checking whole-window inventory. Set manifest `complete`, `inventory_complete`, `lifecycle_complete` only after verifying the instance list against pod/restart history. Each source needs `lifecycle_verified`, `rotation_verified`, `retention_verified`, and `producer_exit_code: 0`; verify no restart/rotation/retention gap. Include previous-container logs where available. Timestamps must lie inside the source's declared covered/lifecycle interval; they do not prove continuous coverage. A retrospective `kubectl logs --since-time` read may include lines after the comparison end: declare the full verified source interval and match its total input line count, while the classifier counts protected events only inside the requested window. Capture near the endpoint where possible; if retention/rotation or an expanding source makes completeness unverifiable, report unknown. For zero source lines set both timestamps to JSON null, and certify inventory and retention independently. An unavailable interval is **source coverage unknown**. Do not use `kubectl logs deployment/...`, which silently chooses one current instance. Keep the inventory in a protected operator location, not the public repository. Source pod/container logs remain raw and cluster-admin accessible.

For each inventoried instance, use the read-only capture option below; `coverage.json` contains the **whole-window** independently verified inventory. Run once per declared `(pod_uid,container_id,log_source)` and store each JSON receipt in a fresh private directory. The helper observes the pod UID and physical current/previous container ID immediately before and after `kubectl logs`, rejects a restart or changed identity, checks the producer exit code, and then checks actual input line count and first/last timestamps against that source. Its binary reader drains oversized lines in bounded chunks and rejects malformed or invalid-encoding input. No bare caller identity or shell pipeline status certifies a physical source. Never enable shell tracing or save raw source lines.

```bash
python3 scripts/hindsight-source-counts.py \
  --start-utc "$START" --end-utc "$END" --coverage-file coverage.json \
  --capture-pod "$POD_NAME" --pod-uid "$POD_UID" \
  --container-id "$CONTAINER_ID" --log-source "$LOG_SOURCE" \
  > "<private-receipts-directory>/<instance>.json"
```

The helper selects `kubectl logs --previous` only for a declared previous physical container. Delete a failed or empty receipt before aggregation. After saving one receipt per source, run `python3 scripts/hindsight-source-counts.py --start-utc "$START" --end-utc "$END" --coverage-file coverage.json --receipts-dir <private-receipts-directory>`; it rejects missing, duplicate, impossible, unbound or mismatched source receipts before reporting a whole-window aggregate. The classifier emits fixed categories only. A generic worker `failed:` suffix certifies a worker failure, even when its arbitrary exception text says 429; only the dedicated Codex quota warning is counted as provider-specific evidence. `worker_timeout`, auth error and Codex quota warning counts remain lower bounds. Inner provider retries may leave no matching line. Provider 429 and terminal outcome completeness require separate protected evidence for a later trial; zero logged evidence alone cannot satisfy those guards.

For log safety, query `sum by (pod_uid,event) (count_over_time({job="hindsight-api-safe"} | json | event=~"scheduled for retry at|deferred until|timed out:|failed:" [30m]))` at the UTC window end (using the matching duration). First verify every source receipt, then sum source counts for containers sharing a `pod_uid`; compare those four fixed worker-event counts with Loki for the **same `pod_uid` and period**. Aggregate across UIDs only after every UID passes. A zero accepted count is normal when the verified source exceptional-event count is zero. Apply the same Prometheus/Loki endpoint convention and inspect boundary events if counts differ. Do not query or export raw message suffixes. Compare `increase(promtail_dropped_entries_total{reason=~"hindsight_unrecognized|hindsight_oversized"}[30m])` per API source-log volume, not in isolation. Existing Loki entries and node pod logs remain outside the new sanitizer; only newly collected safe-job lines have this boundary.

A later reviewed retain-2 trial requires complete equal-window sources, no unknown comparator, and a predeclared rollback. For each protected error count (provider 429, auth refresh, worker timeout and readiness failures), abort on any trial count when both reference windows are zero, or at **twice the larger nonzero reference count**. Abort when a matching LLM/recall/reflect p95 exceeds 1.5 times the larger reference p95; when a bank's 30-minute completion rate drops below half the smaller reference rate while its pending count rises; or when DB waiting persists five minutes. For a 10-minute early check, compare against equal 10-minute reference slices rather than scaling a 30-minute count. Roll back retain cap to 1 through reviewed GitOps and preserve global cap 2. Any missing series or incomplete protected source suspends the trial. No paid canary or new bank write is required for this first rollout.

## Comparison input contract

`trial_regressions` is deliberately unavailable for decisions in this rollout: it returns `incomplete comparison` even when caller-supplied completeness flags are true. No protected, window-bound provider or terminal-outcome producer exists yet, and those flags cannot certify one. Its internal candidate arithmetic remains synthetic-only. A later receipt-backed contract must identify each protected source and exact UTC window, prove completeness and producer status, and bind counts to that source. Before enabling the comparator, predeclare at least 100 histogram observations for **each** LLM scope and recall/reflect bank/operation in **each** window, leaving at least five observations in the upper 5% tail; zero or missing observations are unknown. Completion estimates need validated raw counter deltas or a justified nonzero uncertainty interval tied to scrape samples. An interval that overlaps the half-rate cutoff is unknown, including a borderline 4.999999999 versus 10 extrapolated estimate. Preserve matching bank/scope keys, contiguous equal UTC windows, finite nonnegative values and covered measured-zero trial throughput. A trial cannot infer provider health, successful terminal outcomes or runnable queue depth from native metrics.
