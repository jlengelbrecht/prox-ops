# openbao-hsm

OpenBao on Debian trixie, with what a YubiHSM 2 seal needs. It is built by `.github/workflows/openbao-hsm.yaml` and published as `ghcr.io/jlengelbrecht/openbao-hsm:sha-<commit>`, with `:main` moved to the tested digest. Consumers follow `:main` with a pinned digest.

## Why not the official image

The official image is Alpine (musl). The `kms-pkcs11` plugin and Yubico's `yubihsm_pkcs11.so` are glibc, and the module dlopens libcurl and libcrypto, so they can't run there. This image contains:

| Path | What | Source |
|---|---|---|
| `/usr/bin/bao` | static OpenBao binary | official image, digest-pinned |
| `/usr/lib/openbao/plugins/openbao-plugin-kms-pkcs11` | kms-pkcs11 plugin | plugin image, digest-pinned |
| `/etc/openbao/plugin-kms.hcl` | plugin stanza with the sha256 of the binary above | generated at build |
| `/usr/lib/x86_64-linux-gnu/pkcs11/yubihsm_pkcs11.so` | Yubico PKCS#11 module, HTTP backend | Debian `yubihsm-pkcs11` / `libyubihsm-http2` 2.6.0-5 |
| `/usr/local/bin/docker-entrypoint.sh` | minimal entrypoint at the path the Helm chart calls | this directory |
| `/bin/sh` → busybox ash | the chart stops bao through its preStop, `kill -SIGTERM $(pidof bao)`, because PID 1 is the chart's `sh` and not bao. dash, and bash in sh mode, reject that syntax, so pods would only stop through SIGKILL | Debian `busybox` |

It runs as `openbao`, uid 100 / gid 1000, the OpenBao Helm chart's defaults. The working directory is `/home/openbao`, which must not contain a `yubihsm_pkcs11.conf`: the module reads one from the working directory before `YUBIHSM_PKCS11_CONF`. The image carries no secrets or configuration.

## Using the plugin

The build writes `/etc/openbao/plugin-kms.hcl`. It declares the baked-in binary with `command` and the sha256 computed during that build. Nothing is downloaded at runtime, and OpenBao re-checks the sha256 before every exec. Load it next to the main config:

```sh
bao server -config=/tmp/storageconfig.hcl -config=/etc/openbao/plugin-kms.hcl
```

With the Helm chart, set `server.extraArgs: "-config=/etc/openbao/plugin-kms.hcl"`. The seal stanza in the main config then uses `lib = "yubihsm"`.

The plugin's environment contains only `YUBIHSM_PKCS11_CONF=/openbao/userconfig/yubihsm/yubihsm_pkcs11.conf`, so provide the module's settings there. Use a ConfigMap named `yubihsm` with a `yubihsm_pkcs11.conf` key, mounted through the chart's `server.extraVolumes` (`type: configMap, name: yubihsm`). The chart mounts that at `/openbao/userconfig/yubihsm/` as a whole directory, so updates propagate. The chart's own `/openbao/config` ConfigMap holds only its rendered server config, and it can't take extra files.

## Updating

The images are pinned by digest, and the Debian packages by version. A Renovate bump of a `FROM` line (OpenBao, the plugin, or Debian) is therefore the whole update. The plugin checksum is regenerated by the build, and CI runs the smoke test and `test-softhsm-unseal.sh` on the result. That test proves this `bao` and plugin can initialise, restart and auto-unseal through a PKCS#11 token; Yubico's module needs a real device, so the first replica to restart covers that part. Once `:main` moves, Renovate opens one PR to bump the digest in the HelmRelease and the snapshot job. Only the Debian package pins need a manual bump, when trixie replaces them. The weekly verify run catches that, as it does for yubihsm-tools.
