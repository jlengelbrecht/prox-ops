# Obsidian app bridge deployment contract

This is a desktop plugin for the Kubernetes Obsidian instance only. It stays inert unless Linux Node >=20.8.0 runs it with `OBSIDIAN_BRIDGE_INSTANCE=kubernetes-obsidian` and `OBSIDIAN_BRIDGE_DIR` set to one absolute, owner-controlled ephemeral registry directory. All open vault windows inherit the same two variables. Do not put the directory, registry, credential, or any socket identity file in a vault, retained PVC, plugin setting, or Sync state. No plugin installation or app setting is performed by this package.

Create a fresh 0700 registry directory owned by the desktop UID at each pod lifecycle. Its 0600 `registry.json` has exactly `version`, `instance`, and `endpoints`:

```json
{"version":1,"instance":"kubernetes-obsidian","endpoints":[{"vault_id":"iam","app_name":"IAM Team","app_root":"/config/IAM Team","socket":"/run/obsidian-bridge/iam/iam.sock","credential_file":"/run/obsidian-bridge/iam/credential"},{"vault_id":"homelab","app_name":"Homelab","app_root":"/config/Homelab","socket":"/run/obsidian-bridge/homelab/homelab.sock","credential_file":"/run/obsidian-bridge/homelab/credential"}]}
```

For this example `OBSIDIAN_BRIDGE_DIR=/run/obsidian-bridge`. Create a separate 0700 `<registry>/<vault_id>` directory and 0600 `credential` file for every enrolled vault. Each credential is a distinct 43–128 character URL-safe value generated from at least 32 random bytes. The `socket` field is a required per-vault identity path inside that private directory; **no filesystem socket is created there**. Plugin and Python adapter derive the same Linux abstract AF_UNIX address from that path and credential. Abstract sockets disappear when their listener closes and have no pathname for Node to unlink. A stale or foreign pathname at `socket` is never touched. Node's documented abstract socket support begins at 20.8.0; verify the Node version bundled with the deployed Obsidian app. There is no TCP listener.

The app's exact canonical `FileSystemAdapter.getBasePath()` and `vault.getName()` must select one registry endpoint. Duplicate/nested roots, duplicate IDs/credentials, malformed or noncanonical existing roots, and a missing selected root reject startup. An absent root for another, closed enrolled vault is allowed. The selected root's device and inode are captured at startup and rechecked with canonical path and app identity before operations and immediately before mutations. The Python gateway constructs `BridgeClient` from centrally configured `VaultEndpoint(vault_id, app_name, app_root, socket_path, credential_file)` entries and always passes an explicit vault ID. Methods: `ready`, `list_entries`, `read_note`, `search`, `create_note`, `append_note`, `resolve_embed`. Protocol v1 uses one bounded JSON line per connection; revisions are `sha256:` plus 64 lowercase hex characters over UTF-8 note content. The private protocol is an adapter boundary; the later HTTP gateway must independently authorize writes.

## Required production root pinning and isolation

The plugin attests the selected root against its exact `/proc/self/mountinfo` mountpoint at startup and on each request. The reviewed LinuxServer desktop identity is UID 1000, GID 1000 with `CapEff` exactly zero; any different effective identity or capability mask is inert. An ordinary directory without its own mount entry is inert. Runtime metadata stays outside all vaults. These checks are derived from the process mount namespace, never from an agent-provided flag. The mount must be an individual fixed Kubernetes `subPath` mount for each enrolled vault. Physical mount and desktop privilege verification belongs to the later Kubernetes validation story.

Mount **each** enrolled vault root at its exact `app_root` as an individual Kubernetes `volumeMount` with a fixed `subPath` from the retained volume. The root must be a bind mount in the desktop container's mount namespace, with no symlink at the mountpoint or any ancestor. Before enabling the plugin, deployment validation must attest that each open endpoint's exact canonical `app_root` appears as a mountpoint in `/proc/self/mountinfo`, and that the app's adapter reports that same path. Start the desktop as an unprivileged UID, without `CAP_SYS_ADMIN`, a privileged container, or host mount namespace access. A process inside that desktop then cannot rename or replace the mounted root path. A plain writable directory at `app_root` does **not** meet this prerequisite. The plugin's device/inode check catches replacement observed before a request; it cannot make Obsidian's public API operate through a pinned file descriptor or eliminate an arbitrary external actor's race between check and app write.

Keep the desktop and adapter in one private pod network namespace with `hostNetwork: false` and no untrusted sidecar or same-namespace process. Abstract AF_UNIX has no filesystem permission bit; its address is derived from the private credential and path, and every request must authenticate with that credential. Keep the shared registry and each credential private to the desktop and trusted gateway processes. Do not treat abstract address secrecy as a replacement for credential validation.

Create-only Markdown writes use UTF-8 bytes with public `Vault.createBinary`. The [Obsidian API declaration](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts) specifies that it throws if the file already exists. The bridge re-reads through Vault and verifies the resulting content and revision. The fixture exercises an external creator at the app write boundary; physical Obsidian and Sync behavior remains to be validated.

## Mutation receipts

The trusted bridge adapter first reserves an app-issued random receipt for an exact vault, client, operation, path, content and expected revision. It then sends the mutation with that receipt. The app keeps at most 64 receipts per open vault and at most 64 active mutations across plugin reloads in one process; it rejects further reservations or mutations at capacity and never evicts a running operation. A replay with the same receipt and exact input returns the original committed result without another write. A mismatched replay is denied. The agent-facing `mutation_receipt` tool requires the same original input and the authenticated client's grant; it only reads the receipt and never starts a write. The receipt and result omit note content and credentials.

If the bridge transport expires or disconnects after dispatch, `create_note` or `append_note` returns `status: pending` and the receipt, rather than reporting a failed write. Reconcile that receipt before deciding what to do next. A receipt that cannot be found after plugin or process restart, or after ledger expiry, returns `status: indeterminate`; retrying the old receipt as a mutation is refused. The in-memory ledger does not claim durable proof across app or pod restarts. Terminal and unused reservations expire after 10 minutes; an indeterminate entry remains until app restart. Ledger exhaustion rejects new reservations. A new mutation is a distinct operation and must use the latest note state and the normal create absence or append revision check.

For note and media reads, the plugin calls public `vault.adapter.stat(path)` immediately before full app API reads and checks the returned size, then checks the actual bytes after reading. A concurrent growth after stat can still make a single read allocate more than the cap; Obsidian's public full-read API offers no streaming bound here. Trusted Sync, editor and plugin descendant writers remain outside the public API's atomic confinement guarantee and can produce revision conflicts or path races. They must be trusted or excluded by deployment isolation. Physical app installation, Sync and Hindsight regression, and the canonical-host real IPC gate remain separate acceptance evidence.

Fixture gates: `node --test services/obsidian-mcp/tests/test_bridge_plugin.cjs` and `python3 services/obsidian-mcp/tests/test_bridge.py`. Real AF_UNIX gate: `OBSIDIAN_BRIDGE_REAL_IPC=1 node services/obsidian-mcp/tests/test_bridge_plugin.cjs`. The real gate has no stream double and fails when AF_UNIX bind is unavailable.
